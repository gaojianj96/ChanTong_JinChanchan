# Full Review: C5 YOLO 检测真实化

## 结论：**通过（有条件）** — 核心链路已工程化落地，非stub，但存在需后续跟进的问题

## 分级评估

**P0（阻断级）：无**
Detect() 完整接线：Letterbox→CHW张量→引擎推理→DecodeOutput→PostProcessor NMS→DetectedUnit映射，链路真实闭环，非空表stub。模型权重缺失时由引擎层前置抛出/接管（符合约定），不在本类掩盖。

**P1（重要缺陷）：**
1. **DecodeOutput 硬编码单类别语义错位风险**：`stride = shape[1]`、`classCount = stride - 4` 假设输出严格为 `[cx,cy,w,h,cls...]` 布局，若模型实际是 `(4+nc)×N` 转置或含 objectness 分离项，会静默错解且无校验断言，仅靠测试用例保底。
2. **DetectedUnit 映射语义空洞**：`name: $"cls{d.ClassId}"`、`star:0`、`cost:0`、`items: 空` — 说明分类结果尚未接入棋子/装备知识库，检测框虽真实，但业务语义层仍是占位，需在后续任务显式声明未完成范围。
3. **Letterbox 资源泄漏隐患**：`Detect()` 中 `using (letterboxed)` 正确，但 `Letterbox` 静态方法本身返回未托管的新 `Mat`，若外部调用者（如测试）忽略 dispose 会泄漏；建议文档标注所有权转移。

**P2（建议）：**
- `RestoreBox` 坐标截断用 `(int)x1` 直接截断而非 `Math.Round`，累计像素误差；
- `NonMaximumSuppression`/`ComputeIoU` 为 O(n²) List.RemoveAll，量大时性能可优化，当前测试规模下可接受；
- 测试覆盖解码正例/低分过滤/异常shape/张量归一化，边界较全，但缺 NMS 与 Letterbox padding 的直接单测，仅靠集成路径隐式验证。

**结论**：功能真实化达标，可合入，P1项需登记跟踪票，不阻断本轮。
