# 需求与设计委员会：转型冲刺 DAG 草案研讨 Live

> 主题: 清债 + 视觉数据资产 + M3 起步 DAG 草案 ｜ 日期: 2026-09-12 ｜ 模型: DeepSeek V4.1 Flash / MiniMax M3 / Qwen 3.8 Flash

## DeepSeek V4.1 Flash (需求分析视角)

**结论**：DAG 对 M1 H1-H5、M2 P0 的映射基本完整，但“可验收性”不足，且 A3/C1 存在阻塞 M3 的风险。当前更像任务分解，不是可执行验收计划；对 3840x2088 非等比缩放这一关键新事实，验收口径未落地。

**问题清单**
1. **M1 覆盖但验收缺失**：B1-B5 分别对应 H1-H5，但均无量化的通过标准。例如：热键是否无丢键/卡死？异常退出后 MP4 是否 moov 完整、可播放、时长正确？WGC/D3D 是否无句柄/显存增长？UI 解耦后捕获帧率/延迟阈值？异步落盘队列积压上限、磁盘满策略？无这些则“修复”不可验证。
2. **A1 口径不清**：676 帧“坏帧”定义、分类、双模型冲突仲裁、Opus 代判边界未定义。5 分钟窗口+代判可能引入延迟，且“安全/成本除外”未列明。
3. **A2 标注规范缺失**：50~100 帧中心点指棋盘中心、ROI 中心还是 Anchor？是否覆盖两会话、不同场景？标注一致性、复核比例、金标争议处理均未定。
4. **A3 最大风险**：误差<3px@1080p 未说明 3840x2088 如何映射到 1920x1080。该分辨率宽高缩放比不同（2.0 vs 1.933），若按 16:9 拉伸会掩盖非等比误差。应分别报告 x/y 缩放、每 ROI、最大/均值误差，并输出残差可视化。
5. **C1 阻塞过重**：C1 依赖 A3，C2/C3 又依赖 C1，导致 M3 起步被标注链卡住。契约未明确是否含分辨率、缩放矩阵、ROI、Anchor、时间戳、模型版本、置信度、错误码。
6. **C4-C6 验收空泛**：ONNX 接入验证、YOLO 后处理、PaddleOCR 单帧验证均无准确率、延迟、内存、失败回退指标。
7. **用户诉求偏差**：目标是“最小代价进入 M3、实机数据可用”。A1 全量双层核验可能过度；C1 强依赖 A3 可能不足。Sprint A/B 可并行，但计划未强调。

**改进建议**
- 为每任务补验收矩阵：输入、输出、指标、阈值、证据、负责人。
- A3 明确 3840x2088→1920x1080 的坐标变换：禁止默认拉伸；分别验证 x/y 缩放误差，阈值建议“每 ROI 最大误差<3px@1080p 且均值<1.5px”。
- C1 拆为 v0 草案（先冻结最小字段）与 v1 冻结（A3 后补几何），解除 M3 阻塞。
- A1 定义坏帧分类与仲裁规则；可全量粗筛、关键帧精校，不必全量双模型。
- B1-B5 补回归用例与量化指标，如 MP4 完整性、句柄/显存稳定、队列背压。
- C4-C6 补准确率、延迟、资源阈值及失败回退。
- 明确 Opus 代判边界、审批人与安全/成本例外清单。

## MiniMax M3 (架构设计视角)

**架构评审意见**

**结论**:草案拓扑基本合理,但 C1 粒度过粗、DAG 未反映 C3/C2 独立性、C5/C6 共享后处理未建模,存在三处需修正的架构风险。

**问题清单**

**[P1-1] C1 违反单一职责**
几何元数据(ROI/Anchor/Grid 坐标系/缩放因子)演进节奏随 A3 迭代,服务契约(IFramePool/IInferenceEngine/IGridSlicer 接口)随 C3-C6 固化。合并定义将致 A3 几何变更反复触发接口重写。

**[P1-2] DAG 遗漏 C3 与 C2 独立性**
C3(IFramePool+DI)仅需服务契约,与 C2(Anchor 校准)无调用关系。串行编排使 C2 阻塞 C3 并行机会,延迟 CLI 接入验证。

**[P1-3] C5/C6 未建模共享后处理**
YOLO 与 PaddleOCR 均需 NMS、置信度过滤、ROI 裁剪、绘制。缺共享抽象将致重复实现,维护成本倍增。

**[P2-1] Sprint A/B Recorder 文件冲突**
B1/B2/B5 均修改 Recorder 录制/落盘路径;A1 阶段补录或重放 676 帧时,新逻辑可能破坏既有录制格式或产生半成品 MP4。

**[P2-2] Anchor/GridSlicer 边界模糊**
若 AnchorCalibrator 内嵌 ML 检测(依赖 C4/C5),将在 Vision/Geometry 与 Vision/Inference 间形成循环依赖,违反分层。

**[P2-3] DI 接入时机风险**
C3 注册 Vision 全栈服务,若 C4/C5 阶段契约仍演进,CLI 启动期即抛异常,无法做"仅契约、不推理"的渐进验证。

**改进建议**

1. **拆分 C1**:
   - C1a 几何元数据 Schema(`BoardGeometry`: OriginAnchor/CellSize/ScaleFactor/AspectRatio),依赖 A3
   - C1b 服务契约(IFramePool/IInferenceEngine/IPostProcessor/IGridSlicer/IAnchorCalibrator),可与 C1a 并行
   - C2 依赖 C1a+C1b;C3 仅依赖 C1b

2. **DAG 重排**:
   ```
   A3→C1a─┬→C2(Anchor 校准)
         └→C1b─┬→C3(IFramePool+DI+CLI)
                ├→C4(ONNX)
                └→C4.5(PostProcessor 抽象)→C5/C6 并行
   ```
   新增 C4.5:NMS+ConfFilter+ROICrop 基类,C5/C6 特化复用。

3. **Sprint A/B 解耦**:A1 冻结 Recorder V1 产物只读;B1/B2/B5 在 `RecorderV2` feature flag 下开发,合并前做集成回归。共享文件用 git worktree 物理隔离。

4. **Anchor 分层**:Vision/Geometry/AnchorDetector 用经典 CV(模板匹配/边缘),无 ML 依赖;Vision/Inference/AnchorRefiner(可选)做 ML 精修,依赖 C4。GridSlicer 仅消费 AnchorDetector 输出。

5. **DI 渐进接入**:C1b 确定容器(建议 `Microsoft.Extensions.DependencyInjection`,.NET 8 原生);C3 先注册 `StubInferenceEngine`,CLI 加 `--vision-dry-run` 走通管道;C4 完成后替换真实实现,缩小集成爆炸半径。

## Qwen 3.8 Flash (反方风险视角)



## 反方风险评审意见

**结论：计划整体逻辑成立，但 Sprint A→C 存在单点脆弱链路，Sprint B 并行策略有隐性资源竞争。建议追加 3 项前置门禁后方可放行执行。**

---

### 一、三大失败反例

**R1｜Golden Set 场景坍缩（致命）**
676 帧仅来自 2 个会话，极大概率覆盖同一段位、同一英雄池、同一 UI 状态（如全程 8 人口）。50~100 帧若从中抽取，几何标注对 9 人口满编溢出、特殊装备栏（如 6 件神装）、不同 DPI/显示器偏移**零覆盖**。后果：A3 验证"通过"→C2 校准在真实对局中角点漂移 >15px→C3/C4/C5/C6 全链返工。

**R2｜非等比缩放下 3px 标尺失效**
3840×2088 宽高比 1.839，x 缩放 2.0×、y 缩放 1.933×。"误差<3px@1080p"换算后 x 方向 ≈6px、y 方向 ≈5.8px，且**网格边缘累积误差与中心不同步**。若切片代码按等比假设写，四角点误差可达 8~10px，A3 用单一阈值判定会产生"中心过、边缘不过"的假阳性/假阴性。

**R3｜B1-B5 并行资源死锁**
B1（全局 Hook 消息泵）与 B3（WGC/D3D 资源释放）共享 `IDXGIOutputDuplication` 生命周期；B2（MP4 完整性）与 B5（异步落盘）竞争同一 `fsutil` 句柄池。若两人并行提交，WGC 帧缓冲引用计数归零时 B4 渲染线程仍持有→AV 崩溃或静默丢帧，且 CI 无法稳定复现。

---

### 二、最可能拖入返工的步骤

**C2 Anchor 运行时校准骨架。** 它是 A3 几何结论的"真实压力测试"。一旦 A3 的 Golden Set 覆盖不足（R1），C2 在第二对局即暴露系统性偏移，回溯修改 A3 标注 + 重跑切片 + 重定义 C1 Schema，M3 起步至少延期一个冲刺。

---

### 三、风险应对策略

| 编号 | 措施 | 插入位置 |
|------|------|----------|
| M1 | A1 核验报告须含**场景多样性矩阵**（人口数/装备数/阶段），不达标则强制补录 2 个异构会话再进 A2 | A1→A2 门禁 |
| M2 | A3 验收标准改为**分轴阈值**（x≤6px, y≤5.8px）+ 四角点独立判定 + 边缘 10% 区域加严 | A3 验收 |
| M3 | B1/B3 标记为**串行对**（同一 PR 或前后依赖），B2/B5 标记为**文件锁互斥**，其余 B4 可并行 | Sprint B DAG |
| M4 | C2 验收用例必须包含 ≥1 个 A1 未覆盖的新场景，否则视为未通过 | C2 验收 |
| M5 | 双层核验员仲裁协议（分歧帧→人工裁决）写入 A1 执行 SOP，避免标注噪声污染 A2 | A1 启动前 |

---

**一句话：当前 DAG 的最大风险不在代码债（B），而在"用有限数据验证几何→用有限几何驱动校准"的链式假设。补录数据 + 分轴阈值 + B 串行约束，三项成本极低，收益是避免 M3 整体回炉。**
