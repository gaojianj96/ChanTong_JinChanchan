## 1. Issue #8：ROI 自适应映射器 Review

## 2. Issue #9：六角网格与备战席切片 Review

### 2.1 核心疑虑：几何模型是否匹配游戏实际渲染

这是本次评审 **最关键的风险点**，也是仅凭文字描述无法排除的问题：

> TFT 棋盘在游戏内是**斜 45° 俯视透视视角**渲染的伪 3D 棋盘，而非严格的正交等距六边形网格。靠近摄像机（屏幕下方）的格子在屏幕空间中显著更大，远处（屏幕上方）格子更小、更扁。仅用"奇偶行水平偏移"的**平面等距六角几何模型**，在理论上只能保证网格的拓扑正确性（相邻关系、行列索引），**不能保证在真实分辨率截图上格子边界与像素完全对齐**。

需要明确回答：

1. 该几何模型是**理想抽象网格**（仅用于定义 28 个格子的相对拓扑与近似中心点），还是**声称能精确裁切出格子边界供 OCR 直接识别**？两者对精度要求完全不同。
2. 若是后者，是否有针对透视畸变的补偿系数（例如逐行独立的缩放/偏移系数，而非全局统一 offset）？
3. 测试中的"六角网格几何分布验证"验证的是数学模型自洽性，还是与**真实采集帧的人工标注坐标**的比对？如果是前者，本质上是"测试自己验证自己"的循环验证，无法证明模型真的贴合游戏画面。

**建议**：Issue #9 验收前，必须提供至少 **5~10 张不同分辨率真实对局截图**，将 28 个 BoardHexSlot + 9 个 BenchSlot 的裁切框**叠加绘制**在原图上人工肉眼核验，而不是仅看单元测试绿色。这是切片类任务的黄金验收标准，测试数量再多也替代不了这一步。

### 2.2 输出数据结构问题

- `BoardHexSlot` / `BenchSlot` 是仅包含 **矩形 bounding box**，还是同时提供**多边形顶点（真实六边形轮廓）**？
  - 若仅矩形裁切，六边形格子的矩形外接框必然包含相邻格子的边角像素污染，对后续棋子头像识别影响有限，但对精细 OCR（如星级、装备图标识别）会引入干扰像素，建议同时保留 mask/polygon 供 M3 精细任务使用。
- Slot 的行列索引编号规则（`row, col` 从哪个角开始，是否与游戏内部棋盘坐标系或社区通用坐标系一致）是否有文档说明？这关系到 M3/M4 上层业务逻辑（走法记录、复盘分析）能否直接复用，建议显式定义并写入代码注释/文档。

| 异常路径测试 | null frame、超界坐标、宽高比为 0、极端 letterbox（如 1x1 分辨率）等边界/异常输入是否有覆盖？ |
| 性能基线 | GridSlicer 在实时管线（假设 M3 需要 10-30fps 推理）中单帧处理耗时是否有 benchmark？六角几何计算 + 28+9 次裁切在高频调用下的 CPU 占用需要量化。 |
| Mutation / 断言强度 | 是否存在"测试跑通了但断言过于宽松（如仅检查非空、不检查具体数值）"的水分测试？建议抽样复查 10~15 个测试用例的断言粒度。 |

---

## 4. M2 验收结论

**结论：条件通过（Conditional Pass）**

架构设计思路（Canonical 基准 + 等比映射 + 强类型输出）是合理且专业的工程路径，方向正确。但由于：

1. 未提供实际代码，无法核实缩放算法、边界保护、坐标累积误差等高风险实现细节；
2. 六角网格几何模型是否补偿了游戏真实透视渲染，缺乏证据；
3. 147 项测试的"含金量"（是否有真实图像回归验证）未知，存在"数字漂亮但未真正验证视觉贴合度"的风险。

**在以下证据补交并通过复核前，不建议正式关闭 M2：**

- [ ] 提供 `RoiMapperService` 核心缩放/偏移函数源码片段（重点看 letterbox/pillarbox 分支与舍入方式）
- [ ] 提供 5-10 张真实分辨率截图叠加 28 格 + 9 席裁切框的可视化核验图
- [ ] 明确六角网格模型是否含透视补偿，若无，给出精度误差评估（单位：px）
- [ ] 补充跨分辨率（含非 16:9、DPI 缩放）测试矩阵及结果
- [ ] 明确 BoardHexSlot/BenchSlot 输出结构（矩形 vs 多边形/mask）

## 5. M3 衔接建议

若上述证据补交通过，进入 M3（视觉识别推理管线）时建议：

1. **输出尺寸标准化**：GridSlicer 裁切出的每个 slot 图像建议统一 resize/letterbox 到模型输入固定尺寸（如 640x640 或自定义正方形），并在文档中明确 resize 策略（等比 pad 还是直接拉伸），避免棋子头像/装备图标畸变影响识别率。
2. **反向坐标映射 API**：M3 模型在切片图上输出的检测框/识别结果，需要一个 `SlotToCanonicalCoordinate` / `CanonicalToScreenCoordinate` 的逆映射接口，用于后续 UI 高亮、复盘标注、跨分辨率还原。建议在 M2 收尾时就把这个逆变换接口设计好并加测试，避免 M3 返工。
3. **色彩空间/通道一致性**：明确切片输出的图像格式（BGR/RGB、8bit/16bit），与训练视觉识别模型时使用的预处理管线保持严格一致，否则会出现"训练集/推理集分布不一致"的隐蔽精度损失。
4. **建立视觉回归基线库**：将 M2 阶段收集的真实标注截图沉淀为**永久回归测试集**（golden dataset），M3 训练模型迭代时可复用同一批切片验证推理管线稳定性，同时避免每次修改 GridSlicer 几何参数时无声破坏下游模型输入分布。
5. **透视/几何自适应的长期风险登记**：若确认当前六角网格是**理想拓扑模型**而非像素级精确切片，建议在 M3 立项之初就在风险登记表中记录该假设，并预留"视觉检测框自适应校正 canonical 网格坐标"这一环节，而不是完全依赖静态几何切片的裁切精度。

---

**总评**：工程骨架专业、命名规范、分层清晰，具备工业级项目的雏形。但作为进入模型推理阶段的"地基工程"，视觉切片精度的证据链条目前还不完整，**建议先补证据再拍板结项**，避免 M3 建立在一个未被真实图像验证过的几何假设之上。
