# 独立审查:Contract B3(WGC/DXGI 资源生命周期)

**结论:Pass-with-Notes**(P1×2、P2×4,均为非阻塞;H4 契约语义已闭环)

## 分维度
- **需求符合度**:满足。Closed/DeviceRemoved → 停机+释放+CaptureEnded;事件均在锁外触发(Dxgi `FinalizeCaptureFailure`、WGC `OnItemClosed`、服务 `OnProviderCaptureEnded` 均在退出 lock 后 Invoke);幂等由 `failureFinalized`/`ReferenceEquals(provider,sender)`/provider `running` 三重保证;重启重建 provider/device,成立。
- **架构**:WGC 以 `IWgcFrameProvider` 抽象隔离,可测试性好;Dxgi 未走同抽象,两条路径语义重复但可接受。
- **正确性/边界**:**P1-1** 有界 Channel `DropOldest` 静默驱逐最旧帧,`TryWrite` 返回 true,evicted `CapturedFrame.Mat` 永不 Dispose → 高 fps 下非托管内存持续泄漏(两个服务同一模式;测试用例 2 恰好触发但未检测)。`OnFrameArrived` 若无订阅者亦泄漏(P2-2)。
- **并发**:Stop/Ended/Failure 三方竞争受锁+标志保护,未发现死锁。**P1-2**: WGC 失败路径 `_ = DisposeEndedProviderAsync` fire-and-forget,`DisposeAsync` 返回不保证释放完成;Dxgi 失败后重启会覆盖旧 `captureCancellation`/`captureTask` 引用,旧 CTS(实现 IDisposable)泄漏。
- **安全/性能**:无敏感面;`Task.Yield` preventing busy-spin。**P2-4**:Dxgi 在锁内执行 `D3D11CreateDevice`/`DuplicateOutput` 阻塞调用,可取锁期间阻塞 Stop(可记录的取舍)。
- **错误处理**:**P2-1** Dxgi `StopAsync` 中 `runningTask.WaitAsync(cancellationToken)` 若 OCE 抛出则跳过 `ReleaseDxgiResources`;WGC provider `StopAsync` 先 `ThrowIfCancellationRequested` 再释放——取消 token 导致资源不释放。
- **兼容性**:`GraphicsCaptureSession.IsSupported` 检查、AccessLost→失败信号,合理。
- **可维护性**:职责清晰;provider 释放流程在 4 个文件重复,建议统一函数。
- **测试覆盖率**(P2-3):WGC 路径覆盖充分(含 CaptureEnded+dispose 异常吞没);`DxgiCaptureService` 完全无单元测试(FinalizeCaptureFailure/重启未验证);`WaitForAsync` 超时不断言,静默通过产生假阳性风险。

## 问题清单
| 级 | 证据 | 说明 |
|---|---|---|
| P1-1 | 两处 `channel.Writer.TryWrite` 仅处理 false 分支 | DropOldest 驱逐帧 Mat 未 Dispose,内存泄漏 |
| P1-2 | `FinalizeCaptureFailure` 后 `captureCancellation` 未 dispose;`_ = DisposeEndedProviderAsync` | 重启/旁观释放泄漏旧可取消资源;释放完成无保证 |
| P2-1 | Dxgi `WaitAsync(cancellationToken)`、WGC provider `ThrowIfCancellationRequested` | 取消即跳过释放路径 |
| P2-2 | `FrameReady?.Invoke` 无人订阅路径 | CapturedFrame 泄漏 |
| P2-3 | Dxgi 无测试、`WaitForAsync` 无失败断言 | 覆盖率/假阳性 |
|P2-4|Start 锁内同步设备创建|可接受的取舍,记录|

建议:P1-1 改为自维护环形缓冲(OnEvict 时 Dispose)或封装 channel写端;P1-2 在失败路径同步取消并 dispose 旧 CTS;P2-3 至少补 Dxgi Finalize 路径的可注入工厂测试。修复 P1 项后可转 Pass。
