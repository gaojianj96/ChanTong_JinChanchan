# C4 Review - Claude Sonnet 5

# Full Review 结论

**结论:不通过(Conditional No-Go)**,建议标记为 **C 级(需修复后重测)**

## 关键问题

1. **`EvaluateLatencyGate` 的门禁逻辑本身可信,但测试覆盖不了 `ProbeLatency`**,而后者才是真正产生 `MeanMs` 输入的地方。当前"244/244×3 全绿"只验证了纯函数分支(阈值比较+sqrt clamp),对探针的正确性(零张量占位输入是否会导致某些模型内部分支/NaN 行为异常、动态维度处理是否稳健)完全没有验证,CI 与真实场景之间存在断层,依赖"留实机 receipt"属于**未闭环风险**,不应视为等同于集成测试通过。

2. **设备回退状态污染**:`LoadModel`/`CreateSessionForProbe` 在 DirectML/CUDA 失败后会把 `_currentDevice` 永久改写为 `Cpu`,且发生在 `lock` 内但会跨调用持久生效。如果 `ProbeLatency` 探测时因偶发原因(显存不足/驱动瞬时故障)回退到 CPU,该实例后续所有 `LoadModel`/`RunInference` 都会被錘死在 CPU,不会重试 DirectML/CUDA。这对"设备回退"语义存在歧义,应明确是永久回退还是每次尝试。

3. **`ProbeLatency` 中 `_currentDevice` 的写入无锁保护**:`CreateSessionForProbe` 在 `lock(_lock)` 内被调用创建 session,但返回后 `using(session)` 块中的 warmup/iteration 循环脱离了锁,如果与 `LoadModel` 并发调用,`_currentDevice` 字段可能被并发读写,存在数据竞争。

4. **零张量占位输入的维度假设**:动态维度(`dims[i] <= 0`)直接填 1,对于要求 batch>1 或最小分辨率的模型可能触发 shape mismatch 异常,ProbeLatency 会直接抛出而非给出可诊断的错误信息。

5. **降采样因子语义**:`sqrt(threshold/mean)` 假设延迟与分辨率的平方成正比,这是一个建模假设,未见任何依据或引用,应在 Note 或文档中标注为经验估计,避免被误当作精确校准值使用。

## 建议

- 补充针对 `ProbeLatency` 的**契约测试**(可用极小自制 ONNX 模型或 mock `InferenceSession` 抽象层),不要完全依赖实机 receipt。
- 明确设备回退策略文档化(永久 vs per-call),并加日志告警。
- 修复潜在的并发写 `_currentDevice` 问题。
- 在 `GoNoGoResult.Note` 中注明降采样公式为启发式估计。

待以上项修复并补充最小集成测试后可复审为 B/A 级。
