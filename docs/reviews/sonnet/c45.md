# C4.5 Review - Claude Sonnet 5

# Full Review 结论

核心逻辑正确:严格 `>` 阈值抑制、"等于保留"语义、稳定排序键(conf→class→x→y)、ROI 中心点判定、MaxDetections 截断均按预期实现,测试覆盖到位且断言合理。可合入,但存在若干可提升项。

## 阻断级(Blocker)
无。

## 严重(Major)
1. **`Rect.Width/Height` 为 `int`,面积计算存在潜在整数溢出风险**:`ComputeIoU` 中 `interW`/`interH` 为 `int`,虽已 cast 为 `double` 计算面积,但 `x2 = a.X + a.Width` 若坐标接近 `int.MaxValue` 会先溢出再转换,建议 `Rect` 字段先转 `long`/`double` 再运算。生产场景概率低,但边界防御性不足。
2. **`MaxDetections` 截断发生在 NMS 之后但排序仍是全局稳定排序**——若 `kept.Count` 远大于 `MaxDetections`,`GetRange` 只是简单截断,语义上等价于"保留前 N 个已排序结果",这是合理的,但需在 XML 文档/接口注释中明确该行为契约,当前无说明,调用方可能误解为按类别配额截断。

## 中等(Minor)
3. `ComputeIoU` 对 `Width<=0 || Height<=0` 的退化 Rect 未做防御,若上游产生零宽/负宽框会静默得到 IoU=0,建议在候选过滤阶段加校验或至少注释说明假设。
4. NMS 为 O(n²),`MaxDetections=256` 默认场景可接受,但候选数极大时(如未过滤前上千候选未经置信度预筛)可能成为性能瓶颈,建议 benchmark 补充。
5. `PostProcessOptions.RoiBounds` 使用 `Rect?`,但 `Rect` 为 struct 值类型,模式匹配 `is Rect roi` 可读性一般,可用 `.HasValue`/`.Value` 更符合惯用法(非强制)。

## 建议(Nit)
6. `suppressed` 数组可读性 OK,但可考虑对大 N 场景使用 `BitArray` 降低内存(收益有限,暂不必要)。
7. 测试 `Nms_IoUAtThreshold_IsKept` 命名与实现清晰,建议补充一条 `IoU 严格大于阈值即抑制` 的边界值(如 threshold+ε)显式用例,增强回归防护。

**结论:批准合入**,Major 项 1、2 建议后续 ticket 跟进,不阻塞当前发布。
