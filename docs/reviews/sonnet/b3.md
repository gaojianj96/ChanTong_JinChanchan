# Contract B3 审查结论：**Pass-with-Notes**

## 问题清单

**[高] `WindowsGraphicsCaptureFrameProvider.OnFrameArrived` 锁外触发 CaptureEnded，存在竞态**
`OnItemClosed` 在 `syncRoot` 内执行 `StopAndRelease()`，锁外触发 `CaptureEnded`——符合"事件锁外触发"要求。但 `OnFrameArrived` 检测到设备移除时调用 `OnItemClosed(this, EventArgs.Empty)`，此时若 `item` 已被其他线程置空（例如 `StopAsync` 并发执行），`item.Closed -= OnItemClosed` 会跳过，但 `running` 状态检查在锁内是安全的，不会重复触发。**结论：实际是安全的**，但代码可读性差，建议提取为独立方法并加注释说明双重触发场景（真实 Closed 事件 + 帧循环异常）均收敛到同一收尾路径。

**[高] `DxgiCaptureService.FinalizeCaptureFailure` 与 `StopAsync` 竞态窗口**
`CaptureLoopAsync` 检测失败后调用 `FinalizeCaptureFailure`，该方法在锁内检查 `failureFinalized` 但**未检查 `cancellationToken.IsCancellationRequested`**（该检查在锁外的调用处 `if (failed && !cancellationToken.IsCancellationRequested)`）。若 `StopAsync` 与失败检测几乎同时发生：`StopAsync` 先取消 token 并清空 `captureCancellation/captureTask`，随后 `CaptureLoopAsync` 内的检查 `!cancellationToken.IsCancellationRequested` 为 false，不会误触发——**逻辑正确**，但强依赖锁外判断 token 状态的时序，建议将该判断移入 `FinalizeCaptureFailure` 锁内以增强内聚性和可读性。

**[中] `DxgiCaptureService` 未实现 `IWgcFrameProvider`，CaptureEnded 生命周期测试未覆盖 DXGI 路径**
测试文件 `WgcCaptureServiceTests.cs` 仅覆盖 `WgcCaptureService + IWgcFrameProvider` 抽象层的 `CaptureEnded`/幂等/资源释放路径，`DxgiCaptureService` 的 `FinalizeCaptureFailure`（AccessLost/异常场景）**无单元测试直接验证**。虽然 212 测试全绿，但 DXGI 设备移除场景的 `IsRunning` 收尾与 `CaptureEnded` 触发缺少证据支撑，建议补充针对 `DxgiCaptureService` 的等价测试（可通过注入可控 duplication mock）。

**[中] `WgcCaptureService.DisposeEndedProviderAsync` 吞掉所有异常（包括非 Dispose 相关）**
`catch { }` 空块会掩盖非预期异常（如 `NullReferenceException`），仅测试验证了 `ThrowOnDispose` 场景。建议至少记录日志或区分预期/非预期异常，避免调试困难。

**[低] `DetectDeviceRemoved` 中 `device.DeviceRemovedReason.Code` 访问可能自身抛异常被吞** — 已用 try/catch 兜底返回 true，可接受但语义上"任何异常=设备移除"稍显粗�率，建议注释说明。

**[低] `Contains` 方法用 `Left/Top` 单点判断，未验证 `Right/Bottom`，多显示器边界场景可能选错输出** — 与 B3 无直接关系，但影响 crop 计算正确性，建议后续 ticket 跟踪。

## 逐维度小结
- **需求符合度**：Closed/DeviceRemoved 均收敛到统一停机路径，`IsRunning` 无残留，`CaptureEnded` 锁外触发，服务可重启（`provider = null` 后允许下次 `StartAsync`）——**达标**。
- **并发**：整体加锁模型合理，`ReferenceEquals(provider, sender)` 防止过期 provider 误触发，是亮点。
- **错误处理/幂等**：`failureFinalized`/`StopAndRelease` 幂等保护到位。
- **测试覆盖率**：新增 2 个生命周期测试覆盖正常路径与 Dispose 失败路径，但 DXGI 层缺失对应验证（见上）。
- **架构/兼容性/性能/安全/可维护性**：无重大问题，接口抽象（`IWgcFrameProvider`）便于测试替身，设计良好。

**建议**：合并前补充 DXGI 路径的 CaptureEnded 测试，其余为非阻塞性改进项。
