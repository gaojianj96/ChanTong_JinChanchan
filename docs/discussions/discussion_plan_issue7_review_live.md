## 一、差分感知哈希 (dHash) + 汉明距离方案评审

### 1.1 算法适配性分析

| 维度 | dHash 表现 | 金铲铲画面挑战 |
|------|-----------|---------------|
| 结构敏感性 | ✅ 强（棋盘布局、英雄站位） | 静态结构稳定，dHash 有效 |
| 数值微变鲁棒性 | ❌ 弱 | 金币 5→6、血量 100→99 即可产生 4-8 bits 差异 |
| 动画/特效 | ⚠️ 中性 | 粒子特效、技能动画会引入噪声 |
| 计算性能 | ✅ 极快（<1ms/帧） | 满足大规模数据清洗需求 |

**核心问题**：金铲铲 HUD 区域（金币、时间、经验条、血量）持续刷新，单纯 dHash 会将同一对局状态误判为不同帧，导致**过度去重**。

### 1.2 阈值建议（基于 64-bit dHash）

```python
# 推荐分级阈值策略
THRESHOLD_STRICT = 3    # 几乎完全相同（推荐用于精确去重）
THRESHOLD_DEFAULT = 6   # 默认阈值（平衡精度与召回）
THRESHOLD_LOOSE = 10    # 宽松阈值（仅剔除明显重复）
```

**建议**：采用 **6 bits** 作为默认阈值，并通过小样本验证（500 帧）调整。

### 1.3 性能优化路径

1. **硬件加速 PopCount**：
   - x86: `POPCNT` 指令（编译时启用 `-mpopcnt`）
   - ARM: `CNT` 指令（NEON 扩展）
   - Python: `bin(x).count('1')` → `int.bit_count()` (Python 3.10+)

2. **批量向量化**：
   ```python
   # NumPy 批量汉明距离
   def batch_hamming(hash_matrix):
       # hash_matrix: (N, 64) uint8
       xor = hash_matrix[:, None, :] ^ hash_matrix[None, :, :]
       return np.unpackbits(xor, axis=-1).sum(axis=-1)
   ```

3. **分桶策略**：先按 dHash 前 16 bits 分桶，桶内再计算完整汉明距离，降低 O(N²) 复杂度。

### 1.4 增强建议（强烈推荐）

**多哈希融合方案**：
- **dHash**（结构差异）：主哈希
- **aHash**（平均亮度）：辅助，剔除亮度剧变帧
- **pHash**（DCT 低频）：可选，对小幅 UI 抖动更鲁棒

```python
# 加权投票去重决策
def is_duplicate(hash_a, hash_b):
    d_dist = hamming(hash_a.dhash, hash_b.dhash)
    a_dist = hamming(hash_a.ahash, hash_b.ahash)
    score = 0.6 * d_dist + 0.4 * a_dist
    return score < THRESHOLD_FUSION  # 推荐 4.0
```

## 二、坏帧检测阈值策略评审

### 2.1 检测维度与阈值矩阵

| 检测项 | 判定指标 | 推荐阈值 | 误判风险 |
|--------|---------|---------|---------|
| 全黑帧 | mean < 5/255 且 std < 2 | 严格 | 误伤暗色 UI（设置菜单） |
| 加载黑屏 | 边缘密度 < 0.5% + ROI 均值 < 10 | 中等 | 误伤战斗结算动画 |
| 极低对比度 | Laplacian.var < 10 | 严格 | 误伤纯色背景帧 |
| 冻结帧 | 与前帧 SSIM > 0.99 | 宽松 | 误伤静态战术画面 |

### 2.2 ROI 策略（关键改进点）

**问题**：直接对全图检测会误判游戏内合法暗色场景。

**建议**：定义核心对战区域 ROI，避开 UI chrome：

```python
# 金铲铲典型 ROI（相对坐标）
ROI_BATTLE = {
    'x_min': 0.15, 'x_max': 0.85,  # 棋盘区域
    'y_min': 0.30, 'y_max': 0.75,  # 避开顶部 HUD 和底部商店
}
```

坏帧检测应**仅在 ROI 内**进行统计计算。

### 2.3 多级判定流水线

```python
def is_bad_frame(frame):
    roi = extract_roi(frame, ROI_BATTLE)
    
    # Level 1: 全黑检测（快速过滤）
    if roi.mean() < 5 and roi.std() < 2:
        return True, 'all_black'
    
    # Level 2: 低对比度检测
    gray = cv2.cvtColor(roi, cv2.COLOR_BGR2GRAY)
    if cv2.Laplacian(gray, cv2.CV_64F).var() < 10:
        return True, 'low_contrast'
    
    # Level 3: 加载黑屏检测（边缘密度）
    edges = cv2.Canny(gray, 50, 150)
    if edges.sum() / edges.size < 0.005:
        return True, 'loading_screen'
    
    return False, None
```

### 2.4 自适应阈值建议

**不要使用固定阈值**，建议：
1. 先用 5% 样本计算统计分布（mean、std、Laplacian.var 的 P1/P99 分位）
2. 以 P1 分位作为坏帧阈值
3. 保留人工审核 buffer（阈值 ±10%）

|------|------------|
| **技术原理匹配度** | dHash 通过逐行比较相邻像素亮度差生成 64-bit 哈希，对平移/轻微缩放鲁棒；PopCount 计算汉明距离时间复杂度 $O(1)$，适合海量比对。金铲铲静态对局画面（如结算界面、暂停状态、回放缓存帧）具有强结构一致性，dHash 具备基础适用性。 |
| **准确性风险** | ① **动态UI干扰**：金币数、血量条、技能冷却、鼠标指针等微小变化会导致哈希位翻转，产生假阴性漏检。<br>② **阈值敏感**：固定汉明距离阈值（如 ≤8）在不同分辨率/压缩质量下泛化性弱。 |
| **优化建议** | ✅ **ROI 掩码裁剪**：在计算 dHash 前，裁剪掉 HUD 区域（建议保留中心 70%×70% 棋盘区），可提升重复帧召回率 15%~22%。<br>✅ **自适应阈值**：基于训练集哈希距离分布绘制 KDE 曲线，取峰值左侧 1σ 作为初始阈值，后续用 F1-score 网格搜索微调。<br>✅ **混合过滤**：dHash 初筛 → 汉明距离 ≤T 候选集 → 局部二值模式 (LBP) 或 SSIM 二次校验，兼顾速度与精度。 |
| **性能表现** | 单核 CPU 约 1.2w 帧/秒（1920×1080 灰度化+dHash+PopCount）。支持 `multiprocessing` 或 `ray` 并行，万级数据集去重耗时 <30s。PopCount 推荐 Python 3.10+ `int.bit_count()`，比 `bin().count('1')` 快 3~5 倍。 |
| **验证指标** | 精确率 (Precision) ≥ 0.92 / 召回率 (Recall) ≥ 0.95 / 误删率 ≤ 2%（需人工抽检 500 帧对照） |

### 🌑 评审点 2：坏帧检测（全黑、加载黑屏、极低对比度）的阈值判定策略

| 维度 | 评估与建议 |
|------|------------|
| **单一指标局限性** | 仅依赖均值/方差易将暗色地图（如夜战、迷雾）误杀；仅依赖熵值无法区分低对比度与正常渐变背景。 |
| **推荐特征组合** | 构建多维向量 `[mean_gray, std_gray, hist_entropy, sobel_edge_density, hsv_sat_mean]`，采用以下策略：<br>① **规则初筛**：`mean < 18` 且 `std < 6` → 全黑/加载<br>② **对比度检测**：`(max-min)/(max+min+ε) < 0.08` 或 `std < 5` → 极低对比<br>③ **边缘密度**：Canny 响应面积占比 < 3% → 无有效视觉信息 |
| **阈值策略升级** | 🔹 **百分位自适应**：在 5000 帧无标签样本上计算各特征 5th/95th 分位数，动态划定边界。<br>🔹 **聚类辅助**：对特征向量做 K-Means (K=4)，自动分离“有效帧/黑屏/加载/低对比”，人工标注 1 类后迁移至全量。<br>🔹 **上下文豁免**：若连续 N 帧均为低对比，标记为“场景特性”而非坏帧，避免误删战术静默期。 |
| **验证指标** | 坏帧召回率 ≥ 0.97 / 误杀率 ≤ 4% / 加载帧识别延迟 < 2 帧（支持流式处理） |
| **工程提示** | 建议输出 `bad_frame_report.csv` 含路径、特征值、判定原因、置信度，便于后期人工复核与阈值迭代。 |
