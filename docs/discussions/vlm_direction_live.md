# 识别架构方向变更研讨: OpenCV 定标 + VLM 识别 (Live)

## DeepSeek V4.1 Flash (需求)

①结论：方向成立，但须修正为“OpenCV定位 + 本地确定性识别 + VLM语义补全”的混合管线，而非全交VLM。固定ROI下，YOLO整帧检测性价比低，R5降为可选本地快速路径合理。取舍：YOLO需标注/训练/版本维护，但延迟低、离线稳；VLM零训练、语义强，但成本/幻觉/延迟。主路径用混合，YOLO仅作降级备份。

VLM覆盖判断：弈子名、商店卡语义、装备名/羁绊、海克斯可交VLM；但金币、等级、阶段、血量、经验、商店价格、星级角标、装备小图标不可靠，必须本地OCR/模板/颜色/嵌入。尤其数字与相似小图标，VLM易幻觉，不能作为决策唯一来源。

事件驱动：0.5-2s对回合制决策基本够，但纯帧差会漏关键变化、被动画特效误触发。应“变化格触发VLM + 关键字段低频轮询本地识别”，战斗结算/血量/金币需状态机确认。

②三大风险：
1. VLM幻觉与细粒度误识：关键字段本地化；JSON schema+字典约束；置信度阈值、多帧投票、双模型抽校。
2. 帧差噪声/漏检：ROI稳定检测、状态机、关键字段周期轮询、变化格+全量低频校准。
3. 成本延迟与UI漂移：缓存去重、批量裁剪、预算熔断；校准自检；保留YOLO/模板降级。

③任务拆解顺序：
1. 字段分级：确定性字段 vs 语义字段，定义决策必需精度。
2. 定位与状态机：复用校准/RoiMapper/GridSlicer，帧差+稳定检测+事件总线。
3. 本地识别器：数字OCR、星级颜色/角标、装备模板/嵌入、商店槽状态。
4. VLM识别层：裁剪打包、结构化JSON、字典纠错、置信度。
5. 融合仲裁：本地优先、VLM补全、冲突投票。
6. 评测降级：标注集、混淆矩阵、成本延迟，YOLO备份接入。

## Qwen 3.8 Flash (风险)

①成立：VLM做语义识别+事件驱动可显著降低整帧检测成本，但不应完全替代YOLO。结论：采用混合架构，YOLO/本地检测为高频稳定层，VLM为事件语义层；R5保留为兜底而非可选。

②风险：
1 误识最坏：相似弈子/皮肤、特效遮挡、低画质导致VLM输出错误名/星级/装备。对策：ROI裁剪增强、候选列表限制、季节字典纠错、置信度阈值、双模型抽校；低置信回退YOLO或人工。
2 差量漏检：渐变过渡、变化被特效掩盖、无像素变化但状态含义变（阶段/结算）。对策：关键ROI周期全检、多帧投票、状态机校验；商店刷新、战斗结算强制复核。
3 成本/不可用：突发多格变化、重试、网络故障致预算失控。对策：预算熔断、限流、缓存、token压缩；VLM不可用时切本地YOLO/规则，保证可用。

③任务拆解：1 ROI/校准验收；2 事件检测（帧差+周期采样）；3 裁剪预处理；4 候选/字典约束；5 VLM结构化输出；6 后处理校验（状态机/置信度）；7 本地YOLO兜底；8 评测与成本监控。顺序：先离线评测+兜底，再事件驱动VLM，最后调优成本。
